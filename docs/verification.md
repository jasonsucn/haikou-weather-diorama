## 一、和风天气能否查询海口天气（含预报）

### 结论

**能，但只有 API KEY 不够，还需要你账号专属的 API Host。**

2024 年起和风天气把公共域名（`devapi.qweather.com`、`geoapi.qweather.com`、`api.qweather.com`）替换为**每个账号独立**的 API Host（形如 `abc123xyz.qweatherapi.com`），并计划从 2026 年起逐步停用公共域名。本机实测：

```
GET https://devapi.qweather.com/v7/weather/now?location=101310301&key=TESTKEY123
→ HTTP 403  {"title":"Invalid Host","detail":"An invalid or unauthorized API Host."}
```

说明网络是通的、接口存在，但公共 Host 已不可用。**请在控制台 → 设置 → API Host 复制你的专属域名**，连同 API KEY 一起给我。

### 新版接口（v1，按经纬度，1 km 分辨率）

海口市中心取 `20.04, 110.34`（骑楼老街/钟楼一带）：

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 实时天气 | `GET /weather/v1/current/{lat}/{lon}` | 天气现象、温度、体感、湿度、风向风速、阵风、降水、气压、能见度、露点、云量、UV |
| 逐小时预报 | `GET /weather/v1/hourly/{lat}/{lon}?hours=24` | 最多 240 小时 |
| 每日预报 | `GET /weather/v1/daily/{lat}/{lon}?days=7` | 最多 10 天（免费计划通常 7 天） |
| 城市搜索 | `GET /geo/v2/city/lookup?location=海口` | 返回 LocationID、经纬度、时区 |
| 空气质量 | `GET /airquality/v1/current/{lat}/{lon}` | AQI 与污染物 |
| 灾害预警 | `GET /warning/v1/current/{lat}/{lon}` | 台风/暴雨等预警 |
| 天气指数 | `GET /indices/v1/daily/{lat}/{lon}?days=3` | 穿衣、洗车等生活指数 |

> 鉴权：`X-QW-Api-Key: <key>` 请求头（或 `?key=`）。注意：2027-01-01 起 API KEY 的每日请求量会被限制，长期建议 JWT（Ed25519）。
>
> 每小时/每天/每天的接口字段以 `weather/v1` 文档为准；`location=101310301` 这类旧 v7 城市 ID 接口属于兼容接口，仍可用但新项目建议走经纬度。

### 验证方法（拿到 key 后 1 分钟）

```powershell
$env:QW_API_HOST = '你的host.qweatherapi.com'
$env:QW_API_KEY  = '你的key'
node tools/qweather-probe.mjs
```

脚本会依次探测：海口城市搜索、坐标反查、实时、24h、3/7/10 天、AQI、预警、指数，并：
- 打印每项的 HTTP 状态、业务 code、耗时、关键字段摘要；
- 把原始返回存到 `data/qweather/probe-<时间>.json`（**不会记录 key**）；
- 用 GeoAPI 结果确认海口的 LocationID（预计 `101310301`，以实测为准）和四个区的 ID。

### 风险与注意

- 免费计划有调用配额与 QPM 限制；应用里需要缓存（实时 10 分钟、逐小时 1 小时、每日 1 小时）。
- 浏览器直接调 API 会暴露 key，且可能受 CORS 限制；应用用本地 Node 服务做代理，key 只存在服务端环境变量。
- 分钟级降水、15 天预报、台风路径等属于付费能力，按你的账号套餐决定是否启用。
- 数据必须标注来源（和风天气），符合其署名要求。

## 二、微缩城市建模的还原度与精细度

### 已做的验证：Q 版样片 v0

- 预览：`data/preview-draft.png`（960×640，Cycles）
- 资产：`assets/models/haikou_diorama_pilot.glb`
- 生成脚本：`tools/blender/build_diorama.py`（可参数化重建，不是一次性手捏）

样片包含：海面托盘底座、海甸岛、世纪大桥（A 形双塔+斜拉索）、骑楼老街连续拱廊商铺、钟楼、云洞图书馆、CBD 塔楼、椰林、渔船、云朵。

**这是一版“风格与构图对齐稿”**：比例、配色、地标取舍都还没定稿，不作为最终精度承诺；确认方向后再进入正式资产阶段。

### 正式阶段的精度做法（不是“大概像个城市”）

1. **地标逐个建模，按真实特征抓“识别点”**
   - 世纪大桥：双塔形式、主跨/边跨比例、斜拉索扇形、桥面拱度、栏杆颜色；
   - 骑楼老街：连续拱廊、二三层立面开窗节奏、女儿墙、山花、招牌、骑楼柱距；
   - 钟楼：红砖基座 + 白色塔身 + 四面钟 + 攒尖顶的分段比例；
   - 云洞图书馆：白色有机壳体 + 圆形洞口的位置与大小关系。

2. **Q 版是“比例夸张”，不是“细节省略”**
   - 形体圆润化（倒角+细分），但关键轮廓、层数、开间数、构件数量保持真实；
   - 用低多边形 + 平滑法线 + 手绘感配色，保证近看有细节、远看有剪影。

3. **质量门槛（每轮交付都过）**
   - 每个地标至少 3 个角度渲染对照实景照片；
   - 轮廓相似度：在缩略图尺寸下仍能认出是哪个地标；
   - 网格预算：整城 GLB ≤ 15 万三角面，单地标 ≤ 3 万，保证网页 60fps；
   - 材质数量 ≤ 24，全部 PBR 基础参数，不依赖外部贴图（便于打包）。

4. **可迭代**：Blender 脚本参数化（尺寸、层数、开间、配色），你提意见我改参数重出，不用从头做。

### 需要你拍板的三件事

1. **地标清单**：建议核心 4 个（世纪大桥 / 骑楼老街+钟楼 / 云洞图书馆 / 海甸岛椰林海岸），备选（假日海滩、万绿园、火山口、天空之山）选 0–2 个。
2. **底座形态**：方形海面托盘（当前样片）vs 圆形岛屿底座 vs 无底座悬浮。
3. **Q 度**：当前是“微缩玩具”（3 头身建筑、圆角、马卡龙色）；也可以更“绘本插画”（更扁、更手绘）或更“低多边形写实”（更接近真实比例）。
